## Lead amendment R2 after independent review

The initial A/B/C slices are integrated and jointly tested (83 pass). Before runtime wiring, A2/B2 adopt the committed R2 types exactly. C's A1-A6 adapter fixes are integrated; C3 only adds dispatcher cancellation support.

- Receipt lifetime: the SQLite store defaults to 30 days (`DEFAULT_IDEMPOTENCY_MS`), returns `expiresAt`, and may accept a key as new after expiry. `lookupReceipt` returns no expired receipt; `enqueue` removes/replaces an expired key atomically. Existing receipts are checked before body/queue bounds and return `duplicate: true`. Store options may override the positive bounded lifetime for tests/configuration; persisted expiry wins after restart.
- Reply lifetime: retain minimal participant/conversation references independently of message bodies, default 30 days (`DEFAULT_REFERENCE_MS`). `getMessageReference` uses a live body or an unexpired reference. A2 validates replies against this method. A new reply after body pruning works while the reference exists; an expired/missing reference yields an explicit invalid-reply error. Keyed retry receipts still bypass reply validation during their own lifetime. Metadata GC never deletes unread bodies.
- Reconnect is explicit: `rebindPeer(namespace,id,expectedGeneration,endpoint,now)` checks the current generation in the same transaction, requires `endpoint.generation === expectedGeneration+1`, preserves peer ID/name/registration time, and rejects another peer's session/target. `createDirectory.rebind({namespace,peerId,expectedGeneration,endpoint})` validates and calls it. Ordinary register remains immutable. Old queued notifications are superseded; new unread mail schedules one notification for the new endpoint. A claimed old host operation cannot be unsent; the mailbox remains the same stable ID. Host `t3` requires `target.threadId === sessionId` at registration/rebind.
- Coalesce queued notifications per `(namespace,peerId,endpoint generation)`; a burst before dispatch creates one notify. A claimed batch is frozen: messages arriving while it is claimed must remain covered by a subsequent queued batch, never disappear into the completion. At most one queued batch plus one claimed batch per endpoint; reclaim/retry preserves that batch ID. Test burst and enqueue-during-send explicitly, including a lost host response.
- `notificationId` is exactly the stable outbox job ID. Dispatcher claims jobs individually just before host work, not an entire sequential batch whose later leases could expire. Dispatcher imposes its own finite deadline (default 10 seconds), requires lease duration above deadline plus a safety margin, supplies an abort signal, and never waits forever. Adapter absence/deferred does not consume the separate failure budget; thrown/malformed results do. Validate/clamp retry delay, bound backoff, reject duplicate adapter hosts and malformed dispatcher options.
- Complete an all-acked batch as `empty`, without a failure or a false host-send count. Unsupported and exhausted batches use `failNotification` with terminal status. `notificationStatus` is read-only and exposes states/counts/lease/diagnosis for doctor. Every stored host-error diagnosis uses fixed safe texts; never stringify untrusted throws, result bodies or endpoints. The dispatcher must also protect its own catch path, independent of the adapter.
- `prune` removes acknowledged bodies before its cutoff; expires receipts/references by persisted horizon; prunes terminal diagnostics by cutoff. Pending jobs survive until delivery/empty/terminal resolution. The body referenced by a pending job may already be acknowledged/pruned; unread count decides whether a notification remains necessary.
- MCP/CLI operations must take the sender/inbox/ack peer from the explicitly bound connection, never from tool arguments or shared cwd/provider environment. `read` is unacknowledged-only; foreign/unknown ack IDs count zero. Minimal directory operations remain routing, not authentication or governance.
